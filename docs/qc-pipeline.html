SAP QC Pipeline

How a generated SAP (*_protocol.md) is checked against its protocol PDF for faithfulness: are its claims and citations right? Every SAP field cites its source pages, so the check works fact by fact and never sends a whole PDF to a judge. It answers two questions. Coverage: does retrieval reach the cited pages? Accuracy: are the facts right? Accuracy is measured on every fact a risk trigger flags, and on a random 30% of all facts. Completeness (how many fields are filled) is out of scope; the completeness metric already measures it.

Current configuration (qc-pipeline/config.yaml, 2026-10-25)
  • The judge is gpt-5.6-luna, the reviewer model. That overrides D6 (an independent judge) through allow_non_independent_judge, so every run records judge_independent = false.
  • JEV (jev-1.13.0) runs in cascade mode in front of the LLM judge. Facts JEV accepts carry no quote, which relaxes D9.
  • The P3 values are provisional: k = 5, absence τ unset, JEV accept_confidence = 0.9.

The QC pipeline in five stages

How the pipeline fits together

1Prepare: pages, claims, atomic facts

pages.py · deterministic

Page text that matches the citations

  • Runs the generator's own tools/extract_pdf.py and splits on ===== PAGE N OF M =====, so citation page N is page index N (D5, δ = 0)
  • A page with fewer than 20 non-space characters is unsearchable. It is OCR'd through tools/ocr_pdf.py only with --ocr, which is off by default
  • A page is TOC when ≥ 30% of its lines end in dot leaders and a page number
  • clean text drops margin line numbers, which would otherwise match almost any number and hide NUM_MISS
  • Cached by the PDF's hash
claims.py · deterministic

One claim per cited block

  • Imports substantive_blocks, citation_units and the regexes from tools/lint_sap.py, so QC splits the SAP exactly as the linter does
  • Pages are read only after "page(s)" or "PDF". "Sections 1.1–1.3" is not read as pages, and "pages 1–96 reviewed" is a sweep, kept apart from specific pages
  • Each claim records its outcome_block, which the self-contradiction trigger uses
atomize.py · one model call per SAP

Claims → atomic facts (item, value, status)

  • One checkable thing per fact. A list of criteria, arms or time points becomes one fact per element
  • A check confirms that every number and named entity in a fact occurs in its parent claim. Failing claims are re-asked once, then fall back to the rule atomizer
  • status = absent for "not reported", "not applicable", "no other … is reported"
  • Cached by hash of SAP, model and prompt

2Retrieve, and measure coverage

retrieve.py · no model tokens except embeddings

Rank every page for every fact: Topk(c)

The query is section + field + fact text. Numbers come from the fact text alone. Three rankers are fused by reciprocal rank fusion:

  • BM25 over clean page text, with IDF fitted on PDF text only
  • Dense: text-embedding-3-small on 250-word chunks every 200 words. A page scores its best chunk. TF-IDF stands in when no API is used
  • Number match: |N(c) ∩ N(ti)| / |N(c)|, after normalization (0.05 = 5%). Pages scoring 0 are left out of this ranking
  • RRF(i) = Σr 1/(60 + rankr(i)). Tied pages get their average rank, then BM25 breaks the tie. TOC and blank pages are never ranked
Metric 1 · coverage (D1)

Source Recall@k: does retrieval reach the cited source?

Recall@k = (1/|𝒞|) Σc∈𝒞 𝟙[ S(c) ∩ Topk(c) ≠ ∅ ]
  • Reported with the random-pick baseline 1 − C(n−|S|, k)/C(n, k), split by |S| ∈ {1, 2, 3–4, 5+}, and MRR for |S| = 1
  • A fact with no cited page in Topk gets the COVERAGE_MISS trigger
  • calibrate sets k to the smallest value with Recall@k ≥ 0.95 on judge-confirmed facts
  • --perturb re-ranks corrupted copies of the facts. Recall should barely move, which shows that it tracks topic, not correctness

Perturbation check (--perturb, 100 documents, 7,383 facts): each present cited fact that can be corrupted gets an arm swap, a ≥↔≤ flip or a number scaling. Recall@5 moves from 0.88 to 0.76. Retrieval still finds the right page for most wrong facts, so coverage can't stand in for accuracy.

Corrupted-claim experiment: 5 documents, every corruption kind

A closer look at the check above. In 5 documents, every present fact with cited pages gets each corruption from validate/plant.py that applies to it, not just the first that fits. Each corrupted copy is ranked with the production retriever (BM25 + text-embedding-3-small + number match, RRF) and compared with its own original, paired by kind. Only coverage is measured, with no judge. Rewording that changes the meaning but not the words leaves Recall@5 where it was. It drops only when the corruption removes something retrieval matches on: a number, or the whole fact text.

3Route: triggers, plus a random 30%

Each fact is selected twice, independently. Any trigger puts it in T, which is judged in full. A systematic draw puts 30% of all facts in R. A fact in both is judged once.

CodePuts a fact in T when…
NUM_MISSA non-trivial number in the fact is on none of its cited pages
POLARITY≥/≤, upper/lower, one-/two-sided, superiority/NI/equivalence, or an arm label the SAP enumerates disagrees with the best passage on the cited pages
COVERAGE_MISSNo cited page in Topk
SWEEP_ONLYThe only citation is a page sweep ("pages 1–96 reviewed")
ABSENCE_HITSAn absence fact with at least one candidate page
SELF_CONTRAAn absence fact that the SAP answers itself: in its own outcome block (lexicon terms), or anywhere for lint_sap FIELD_TOPICS fields. No PDF needed
LOW_OVERLAPThe best-passage BM25 on the cited pages is in the document's lowest 10%
COMPOUNDThe parent claim produced more than 3 facts
CRITICALSection 2.2, 2.3, 2.5, 3.3, 5.1, 5.3 or 5.4

Frozen as TRIGGERS_VERSION = "v1". Tuning them on the documents they report on would flatter them; R ∩ U measures what they miss.

4Judge: JEV first, then an LLM that must quote

packets.py · evidence for one judge call

What the judge sees

  • Present fact: its top 3 passages (150 words, every 100) from cited pages ∪ Topk, plus one passage from every cited page (pilot C90 failed without this). A coverage miss also gets up to 3 whole cited pages
  • Absence fact: one passage per candidate page, at most 8. A passage holding a lexicon term outranks a higher BM25 score. Ranking by score alone dropped LACE p56, the page that contradicts C96
  • Facts with the same section and kind share a call: about 6, at most 8, on the union of their passages, each sent once
  • Never the generator's evidence.md or review.md (D7)
Verdicts

Allowed answers

Present facts: supported contradicted not_found

Absence facts: consistent contradicted unverifiable

  • minor = true marks a contradiction that is imprecise or incomplete rather than wrong. Strict scoring counts it as an error; lenient scoring doesn't
  • If the protocol contradicts itself and the fact matches one version, the fact is supported, and the rationale says so
  • Rationale ≤ 30 words. Prompt hash, model and tokens go to the cost log

5Metrics

Coverage

Source Recall@k

P̂( rankc(S) ≤ k )

Says whether retrieval reaches the cited pages, and how large k must be.

Doesn't say whether a fact or its citation is correct.

Accuracy on flagged facts

Finding-error accuracy

accT = #correctT / |T|

Says how accurate the flagged facts are. Every flagged fact is judged, so there is no sampling error. Error yield 1 − accT shows whether the triggers find errors efficiently.

Doesn't say how accurate the document is. Flagged facts are risky by design.

Accuracy on a random 30%

Random accuracy

accR = #correctR / |R|,  πi = 0.3

Says how accurate the whole document is, without bias. The errors in R ∩ U give the trigger miss rate.

Doesn't say much for one document alone, so pool across documents.

run_qc.py
  • --doc DIR or --pairs pairs.csv. --stage deterministic runs P1 with no tokens. --backend stub runs the full stage with stand-ins for every model call
  • --workers N runs documents in parallel processes. Workers return their cost rows, so only the parent writes _cost.tsv, and each document also keeps its own cost.tsv in case a worker dies
  • --resume skips documents that already have a full-stage metrics.json and run.json
  • The summary tables are written after each document, so a long run that stops keeps what it finished
  • --jev cascade|shadow|off, --ocr, --perturb, --seed, --k
  • run_qc.py pool for pooled metrics, and run_qc.py calibrate for P3

Validating the judge and calibrating (P3 gate)

Planted errors · validate/plant.py

About 100 facts from several documents are corrupted and mixed blind with their originals. Corruptions: numbers ×{0.6, 0.8, 1.25, 1.5}, arm swap, ≥↔≤, ITT→PP, and a reported item relabeled "Not reported". The planted set is judged with the same retrieval, packets and judge as a QC run.

  • Detection = P(not supported | corrupted), target ≥ 0.90
  • False alarm = P(not supported | original), target ≤ 0.05

Human gold labels · validate/gold_sheet.py

About 100 judged facts, stratified by section, are exported for blind labeling (the judge's verdicts go to a separate key file). Cohen's κ is computed on error vs correct and on the full verdict, with a target of κ ≥ 0.70. Planted errors don't look like real ones (C96 is a real one), so they don't replace this.

Thresholds · run_qc.py calibrate

  • k: the smallest k with Recall@k ≥ 0.95 on judge-confirmed facts (supported, quote verified, with supporting pages)
  • τ: per document, the 1% quantile of the best BM25 score on supported facts' supporting pages, so absence search keeps recall ≈ 0.99. The minimum across documents is used
  • JEV accept_confidence: the smallest τ whose 95% upper bound on JEV-vs-LLM disagreement is ≤ 0.03. Use shadow-mode runs, because cascade runs only pair escalated (hard) facts
